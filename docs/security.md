# Безопасность

Короткие ответы на вопросы, что и как защищено. Обновлено: 2026-09-25 (v0.9.0).

## Модель угроз

Локальный/домашний инстанс в закрытой сети. Если сервер вынесен наружу
(деплой, D5) — действуют пункты «для публичного сервера» в конце.

## Вопросы и ответы

### Кто имеет доступ?

Общий пароль инстанса (D3): **PBKDF2-HMAC-SHA256, 120 000 итераций**, соль
на каждый пароль, сравнение через `hmac.compare_digest` (тайминг-атака
исключена). Пароль задаётся в `/admin`, хранится хешем в `settings`.
API без входа отвечает 401, страницы — редирект на `/login`.
Пока пароль не задан — доступ открыт; по умолчанию сервер слушает только
`127.0.0.1` (для сети нужен явный `HOST=0.0.0.0`).

### Как хранится секрет сессий?

`SECRET_KEY` из env, иначе — сгенерированный 64-hex в `data/secret_key`
(каталог `data/` в `.gitignore`). На публичном сервере задавать `SECRET_KEY`
явно.

### Есть ли защита от CSRF?

Все изменяющие действия — POST. Cookie сессии: `SameSite=Lax` (задан явно),
`HTTPOnly` (по умолчанию Flask). Кросс-сайтовая форма/ fetch не отправит
cookie → `_gate` вернёт 401/редирект.

### Что с XSS?

- HTML глав санитизируется **whitelist-фильтром при импорте** (`parsers`):
  только разрешённые теги, у `<a>` — `href/title/id`, у `<img>` — `src/alt/loading`,
  у остальных — только `id` (якоря сносок).
- **Схемы URL проверяются** (с v0.9.0): `javascript:`, `data:`, `vbscript:` и
  прочие неизвестные схемы → атрибут удаляется; проверка по нормализованной
  строке (браузеры выкидывают `\t\n` из схем — `java\tscript:` тоже отсекается).
  Разрешены: относительные пути, якоря, `http(s):`, `mailto:`, `asset:`, `ftp:`.
- Заметки: экранируются на сервере (Jinja `{{ }}`) и на клиенте (`esc()` в
  `reader.js`).
- Сниппеты поиска: `_escape()` текста, `<mark>` только из маркеров FTS.
- `| safe` используется только для санитизированного HTML глав.

### SQL-инъекции?

Все запросы параметризованные; динамические идентификаторы (имена таблиц в
`UPDATE ... SET rating =`) — только из белых списков в коде. FTS-запрос
собирается из квотированных слов (`_fts_query`).

### Path traversal при отдаче файлов?

`/covers/<name>` и `/media/images/<book>/<name>` — `send_from_directory`
(нормализация пути + запрет выхода за каталог). Тест
`test_file_routes_reject_path_traversal`.

### zip-архивы (бэкап и библиотека)?

- **Restore**: перед распаковкой каждый путь из `namelist()` проверяется через
  `realpath` — выход за пределы временного каталога (zip-slip) запрещает
  операцию; затем `PRAGMA quick_check` базы. Тест `test_restore_rejects_zipslip`.
- **Импорт библиотеки**: ничего не распаковывается на диск «как есть» —
  файлы читаются по именам из манифеста, пишутся только `book_<id>.<ext>` и
  `basename()` картинок.

### Open redirect после входа?

`/login?next=` принимает только локальные пути: начинается с `/`, без `//`
(протокол-относительные), без `\` (браузеры нормализуют `/\` в `//`), без
`..`. Иначе — редирект на ленту. Тест
`test_login_next_rejects_protocol_relative`.

### Лимиты на запросы?

`MAX_CONTENT_LENGTH = 200 МБ`. Ошибки импорта не роняют сервер (F5-карточки);
обход всех GET-роутов без 5xx — тест `test_smoke_all_get_routes`.

## Остаточные риски

| Риск | Статус | Что делать |
|------|--------|-----------|
| Нет rate-limit на `/login` | принято локально | на публичном — fail2ban / лимиты reverse-proxy |
| Нет security-заголовков (CSP, X-Frame-Options) | не сделано | добавить при деплое (D5) |
| Zip-бомба: распакованный объём не ограничен | частично (200 МБ на запрос) | лимит на суммарный размер при чтении |
| Один общий пароль, профили без своих паролей | модель продукта | при необходимости — per-profile пароли (отдельная задача) |
| `data/secret_key` с правами по умолчанию | ок на Windows | на Linux — `chmod 600` |

## Для публичного сервера (D5)

1. HTTPS: Let's Encrypt + reverse-proxy (Caddy/Nginx).
2. `SECRET_KEY` и пароль из env/панели, не дефолтные.
3. fail2ban или лимит запросов на `/login`.
4. Регулярный `python pika.py backup` с выносом архива за сервер.
5. Обновлять систему и Python; `data/` — только под пользователем сервиса.
